# Contributing

This is one person's NixOS, nix-darwin and Home Manager configuration, not a
template, and most of its prose is written by coding agents with human
review. Contributions are welcome from people and agents alike; the same
rules apply to both. This page is the short version. The full text is the
book's [git and agent workflows](book/src/git-and-agent-workflows.md)
chapter, and agents also read [`AGENTS.md`](AGENTS.md).

Do not install the config wholesale: on the impermanence hosts it deletes
`/root` on every boot. See the [README](README.md).

## Many safeguards only trigger under bash

Many of the agent skills and safeguards here only fire when commands run
through the harness's `Bash` tool: the git, `just`, nix and secrets guard
hooks match that tool, and the skills and `just` recipes are written as bash
commands. Another shell (fish, zsh, nushell, PowerShell) or a tool that is
not `Bash` runs without those checks. If you are using one, say so. An agent
should warn the user before it starts, because the user is then the only
check left. What matches what is in
[checks, guards and hooks](book/src/agent-checks-and-guards.md).

## Before you start

- Read [`wiki/00-INDEX.md`](wiki/00-INDEX.md) to find the page for your task,
  and [your first change](book/src/first-change.md) if you are new to the
  tree.
- Work in your own `git worktree`, not a shared checkout:
  `just agent worktree new <branch> --root <scratch-dir>`.
- Stage new files with `git add` before you run `nix eval`. A flake ignores
  untracked files, so a new module does not exist until it is tracked.

## Making the change

- Name the branch and start the commit's first line with a type prefix:
  `feat/`, `fix/` or `docs/`, and `docs: fix the command`. The body says what
  changed, why, and what was verified.
- Agent-authored commits end with a `Co-Authored-By: <agent>` trailer that
  names the agent only, no model and no email. Claude's is
  `Co-Authored-By: Claude`. `just agent commit -- <paths...>` adds it.
- A change that makes a wiki page stale fixes the page in the same change,
  and a page with a `-for-agents` sibling updates both.
- Run `just preflight`. CI runs that recipe itself, so a green local run is
  what CI will see. Without nix or `just`, the git hooks fall back to
  `flake/scripts/offline_checks.py`.
- Say how far you verified: *evaluates*, *builds* or *runs*, and nothing
  beyond what you reached.

## Opening the PR

- Issues and PRs go in `NireBryce/nixos-configs` only. An upstream bug is
  still tracked here, and filing on another project needs the repo owner to
  ask for that filing.
- Follow [`.github/PULL_REQUEST_TEMPLATE.md`](.github/PULL_REQUEST_TEMPLATE.md):
  what changed, why, what was verified, what was deliberately left alone.
  An agent-written PR carries `🤖 Generated by an LLM agent` at the top and
  bottom.
- PRs land on `experimental`. `main` is the promoted known-good branch and
  moves only by a PR from `experimental` after hardware verification.
- For a guard or check, say what it now enforces and how you verified it.
  Security and threat-model notes do not belong in public text.

## Secrets

Secrets are sops-nix. Never decrypt them into a conversation, a log or a PR;
`just read-sops-names` lists the names without values.
