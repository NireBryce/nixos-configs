# Risk and impact ratings

_Last modified: 2026-11-07_

Every PR body, and every issue that proposes a change, ends with two
ratings out of 10 and a one-line reason for each, so a reader can triage
without reading the diff. The PR template, skill `ship` and skill
`propose-issue` point here; this page owns the scale.

```
## Risk and impact

- **Risk: N/10** -- what could break, and how a break would show.
- **Impact: N/10** -- who gains what, and how much.
```

The section goes last, before the `🤖 Generated by an LLM agent` footer.
Skip it where nothing changes: a bug report, a question, a promotion PR
made only of PRs already rated (say so in one line instead).

## Risk: what could go wrong if this change is wrong

Rate the change as written, with its tests; say what the number rests on.

| Score | Means | Examples here |
|---|---|---|
| 1-2 | Text only; a mistake misleads a reader, nothing is built differently | `wiki/`, skills, `AGENTS.md`, comments |
| 3-4 | Tooling or checks change; no host's closure changes | `flake/scripts/`, `.agents/`, `.justfile`, CI, git hooks |
| 5-6 | A host's closure changes, and `just diff` or a build covers it | a package, a Home Manager module, a homelab service option |
| 7-8 | A host could fail to boot, switch or be reached | `fileSystems`/`boot`, networking, sshd, Tailscale, a secret's path or owner |
| 9-10 | Data loss, or a lockout nothing has been run to check | `WARN-impermanence.nix`, `flake/modules/general-config/impermanence/`, sops recipients, deleting or moving users' files |

Raise one step when the change was only evaluated (`nix eval`, `just
check`) and touches a host's runtime; lower one step when it was built and
run on the host (the rungs in `AGENTS.md`, "Before calling it done").

## Impact: what this change is worth if it is right

| Score | Means | Examples here |
|---|---|---|
| 1-2 | Cosmetic; nobody would notice its absence | wording, a rename inside one module |
| 3-4 | Less friction for the user or agents working here | a stale wiki page fixed, a clearer skill, a recipe |
| 5-6 | Fixes a real bug or unblocks a workflow someone hit | a failing recipe, a step that had to be done by hand |
| 7-8 | A capability on a host, or wrong behavior made right | a new service, a package the user needs, a boot or switch failure fixed |
| 9-10 | Recovers a host that cannot be used, or closes an exposure | a host that did not boot now boots; a leaked secret rotated |

## Writing the blurb

One line each, plain prose. Risk names the failure, not the feeling ("a
wrong subvolume name would leave initrd without `root-blank` and the host
would not reach login"), not "low risk". Impact names who gains ("the
handheld can suspend again"). A rating is a judgement, so a reviewer may
disagree with it in the PR; change the number then, not the scale.

Security-relevant changes follow `AGENTS.md`, "Working in this repo": the
blurb says what is now enforced, never what got past the old version.
